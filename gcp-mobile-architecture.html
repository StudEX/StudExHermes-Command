📱 Mobile App Architecture Overview

A single codebase deployed as separate containerized apps for each company, connecting to dedicated GCP VMs with isolated data and branded experiences.

Tech Stack:
  • Frontend: React Native / Flutter (cross-platform iOS + Android)
  • Backend: Node.js/Python API (containerized)
  • Database: Cloud Firestore (real-time) + Cloud SQL (transactional)
  • Infrastructure: GCP Compute Engine VMs + Cloud Run containers
  • Storage: Cloud Storage for files/media
  • Authentication: Firebase Auth + custom JWT
  • Messaging: Cloud Pub/Sub for agent communication

Why This Approach?

  • Single Codebase: Code once, deploy for each company with config changes
  • Container Isolation: Each company has isolated container, data, and VM resources
  • Scalability: Add new company in minutes, not weeks
  • Security: Network-level isolation between company VMs
  • Cost Efficiency: Shared base code, minimal duplicate infrastructure
  • Agent Integration: Mobile apps trigger agent workflows on connected VMs

Component Details

🐳 Cloud Run (Containerized API)

Purpose: Stateless API servers

  • Auto-scales based on demand
  • One container per company
  • Environment variables for config
  • Direct connection to company's VM
  • Built-in monitoring & logging

🖥️ Compute Engine (Company VM)

Purpose: Run agents + operations

  • Dedicated e2-medium or n1-standard-2
  • Runs Hermes + agent infrastructure
  • Private network (VPC peering)
  • Cloud SQL Proxy for DB access
  • Monitoring via Cloud Monitoring

🗄️ Firestore (Real-Time DB)

Purpose: Real-time data sync to mobile

  • Collection per company
  • Live subscriptions (WebSocket)
  • Automatic indexing
  • Security rules per company
  • Offline persistence

🔐 Cloud SQL (Transactional DB)

Purpose: ACID transactions & reporting

  • PostgreSQL or MySQL per instance
  • Automated backups
  • Read replicas for scaling
  • Private IP connections
  • Daily snapshots

🌐 Cloud Load Balancer

Purpose: Route mobile traffic

  • SSL/TLS termination
  • Route by company domain
  • Health checks
  • DDoS protection
  • Global distribution

🔑 IAM & Security

Purpose: Control access

  • Service accounts per company
  • VPC isolation
  • Firebase Auth rules
  • Cloud Armor DDoS
  • Secrets Manager integration

🔗 Mobile App ↔ VM Connection

How Mobile Apps Communicate with Agent VMs

Connection Flow:
  1. Mobile app makes API call to Cloud Run container (https://api.company.com/tasks)
  2. Container authenticates with Firebase Auth
  3. Container routes request to company's GCP VM via private VPC network
  4. VM's Hermes agent processes the request
  5. Agent updates Firestore/Cloud SQL in real-time
  6. Mobile app receives live update via Firestore subscription
  7. Status agents push updates to Cloud Pub/Sub → mobile push notifications

Request/Response Architecture

Synchronous Requests

For immediate responses:

  • Authentication check
  • Data fetch from Cloud SQL
  • Real-time metric reads
  • User profile updates

Asynchronous Tasks

For long-running operations:

  • Mobile app sends task to API
  • Task published to Cloud Pub/Sub
  • VM's agent consumes task
  • Updates stored in Firestore
  • Push notification when complete

Real-Time Subscriptions

For live updates:

  • Mobile subscribes to Firestore doc
  • Agent updates doc on VM
  • Firestore pushes changes to mobile
  • UI updates automatically
  • Offline queuing enabled

🗂️ Per-Company Infrastructure Setup

Creating a New Company Instance (AfricaBiz Example)

Step 1: GCP Project Setup

  • Create GCP Project: africabiz-prod
  • Enable APIs: Compute Engine, Cloud SQL, Firestore, Cloud Run, Cloud Build
  • Create VPC Network: africabiz-vpc (10.0.1.0/24)
  • Create Firewall Rules: Allow port 3000 (API), 5432 (DB proxy)

Step 2: Create GCP Compute Engine VM

gcloud compute instances create africabiz-vm-01 \ --project=africabiz-prod \ --zone=us-central1-a \ --machine-type=n1-standard-2 \ --image-family=ubuntu-2004-lts \ --image-project=ubuntu-os-cloud \ --network-interface=network=africabiz-vpc \ --service-account=africabiz-sa@africabiz-prod.iam.gserviceaccount.com \ --scopes=https://www.googleapis.com/auth/cloud-platform

Step 3: Setup VM with Agent Infrastructure

# SSH into VM gcloud compute ssh africabiz-vm-01 --zone=us-central1-a --project=africabiz-prod # Install Docker curl https://get.docker.com | sh # Start Hermes + Agent Infrastructure docker run -d \ --name hermes-africabiz \ --network host \ -e COMPANY_NAME=africabiz \ -e FIRESTORE_PROJECT=africabiz-prod \ -e CLOUD_SQL_INSTANCE=africabiz-db \ gcr.io/studex-prod/hermes-agent:latest

Step 4: Create Cloud SQL Database

gcloud sql instances create africabiz-db \ --database-version=POSTGRES_14 \ --tier=db-f1-micro \ --region=us-central1 \ --network=africabiz-vpc \ --database-flags=cloudsql_iam_authentication=on # Create database gcloud sql databases create africabiz --instance=africabiz-db # Create user gcloud sql users create africabiz-app --instance=africabiz-db --type=CLOUD_IAM_SERVICE_ACCOUNT

Step 5: Deploy Container to Cloud Run

gcloud run deploy studex-mobile-africabiz \ --image=gcr.io/studex-prod/studex-mobile:latest \ --platform=managed \ --region=us-central1 \ --allow-unauthenticated=false \ --set-env-vars="COMPANY_NAME=africabiz,GCP_VM_IP=10.0.1.5,CLOUD_SQL_INSTANCE=africabiz-db" \ --service-account=studex-mobile-africabiz@studex-prod.iam.gserviceaccount.com \ --vpc-connector=africabiz-vpc-connector

Step 6: Create Firestore Collections

  • africabiz_users - User profiles and authentication
  • africabiz_tasks - Pending and completed tasks
  • africabiz_agents - Agent status and metrics
  • africabiz_messages - Real-time messages
  • africabiz_metrics - Dashboard metrics

🔒 Security & Isolation

Network Isolation

  • VPC Peering: Each company has isolated VPC, peered privately to Cloud Run
  • Firewall Rules: Only allow traffic between company's Cloud Run and VM
  • Private IP: VMs communicate on private network, no public IPs needed
  • Cloud SQL Proxy: Secure connection from VM to database

Data Isolation (Firestore)

// Firestore Security Rules rules_version = '2'; service cloud.firestore { match /databases/{database}/documents { // Company-level collections match /africabiz_{document=**} { allow read, write: if request.auth.token.company == 'africabiz' && request.auth.token.uid in get(/databases/$(database)/documents/africabiz_users/$(request.auth.uid)).data.roles; } // Other companies are blocked match /{document=**} { allow read, write: if false; } } }

API Security (Cloud Run)

  • Firebase Auth: Validate token on every request
  • Company Check: Verify user belongs to company in request
  • Rate Limiting: Limit requests per company (1000/hour)
  • API Keys: Server-side keys for inter-service communication
  • CORS: Only allow mobile app domains
  • HTTPS Only: All traffic encrypted in transit
