🏗️ Architecture: The Four Layers

Layer 1: Mobile Interface (User Entry Point)

User Device (iOS/Android) ↓ React Native App (branded per company) ↓ Firebase Auth + JWT ↓ Cloud Run API Gateway (https://api.company.studex.global)

Layer 2: Command & Control (Human Operators)

Terminal OS Interface (StudEx OS v2) ├─ The Station (Command hub - Overview) ├─ Briefs (Intelligence room - Metrics + Reports) ├─ Outbox (Communication room - Messages + Alerts) ├─ Machines (Infrastructure room - VM status) ├─ Projects (Work room - Tasks + Timelines) └─ Ledger (Finance room - Costs + Revenue) Specialized Centers: ├─ War Room (Crisis response - Real-time decisions) ├─ Factory (Production - Manufacturing operations) ├─ Recovery (System restore - Emergency procedures) └─ Command Red (Escalations - Priority decisions)

Layer 4: Infrastructure (Compute & Storage)

GCP Project (Per Company) ├─ Compute Engine VM (n1-standard-2) │ ├─ Hermes Container │ ├─ Agent Orchestration │ └─ Mission Control Daemon ├─ Cloud Run API (Stateless) │ ├─ REST endpoints │ ├─ WebSocket connections │ └─ Authentication gateway ├─ Cloud Firestore (Real-time) │ ├─ company_users │ ├─ company_tasks │ ├─ company_agents │ ├─ company_metrics │ └─ company_messages ├─ Cloud SQL (Transactional) │ ├─ Users & authentication │ ├─ Transactions & orders │ ├─ Reporting & analytics │ └─ Compliance records └─ Cloud Storage ├─ Backups ├─ Media files └─ Exports

🔄 Data Flow: From Mobile to Agents

Example: User Creates Task on Mobile

1. User taps "Create Task" in mobile app ↓ 2. Mobile app sends POST /api/tasks with task data ↓ 3. Cloud Run validates JWT token (Firebase Auth) ↓ 4. Cloud Run checks user belongs to company + has permission ↓ 5. Creates document in Firestore: company_tasks/{taskId} ↓ 6. Triggers Cloud Pub/Sub event: company-tasks-new ↓ 7. GCP Compute Engine VM receives event ↓ 8. Hermes agent evaluates task: - Priority level (Eisenhower Matrix) - Assign to specialization (Field Ops? Research? Workflow?) - Create sub-tasks - Schedule execution ↓ 9. Agent updates Firestore: company_tasks/{taskId} - status: "assigned" - assigned_to: "field-ops-agent-1" - due_date: calculated ↓ 10. Firestore subscription notifies mobile app ↓ 11. Mobile app updates UI: task shows as "In Progress" ↓ 12. Agent executes work in background ↓ 13. Updates Firestore on completion ↓ 14. Mobile receives update → UI shows "Completed"
